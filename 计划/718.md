## 三、数据库设计（3张表）

```sql
-- 用户表（小程序 openid 登录）
CREATE TABLE users (
  id TEXT PRIMARY KEY,          -- UUID
  openid TEXT UNIQUE NOT NULL,   -- 微信 openid
  nickname TEXT DEFAULT '用户',
  avatar TEXT,                   -- 头像URL
  created_at TEXT DEFAULT (datetime('now'))
);

-- 账单记录表
CREATE TABLE bills (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id),
  type TEXT NOT NULL CHECK(type IN ('income', 'expense')),  -- 收入/支出
  amount REAL NOT NULL CHECK(amount > 0),                    -- 金额
  category TEXT NOT NULL,       -- 分类：餐饮/交通/购物/娱乐/...
  note TEXT,                    -- 备注
  bill_date TEXT NOT NULL,      -- 日期 YYYY-MM-DD
  created_at TEXT DEFAULT (datetime('now'))
);

-- 分类表（用户可自定义）
CREATE TABLE categories (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id),
  name TEXT NOT NULL,           -- 分类名
  icon TEXT DEFAULT 'default',  -- 图标
  type TEXT NOT NULL CHECK(type IN ('income', 'expense')),
  sort_order INTEGER DEFAULT 0
);
```

**面试话术：**
> "后端使用 Vercel Serverless Functions，每个 API 是一个独立的云函数；数据库选 Turso（基于 SQLite 的边缘数据库），免费套餐 9GB 够用，全球多节点访问快。前端通过 RESTful API 联调，JWT 鉴权。"

## 四、API 接口设计（8个接口）

```
POST   /api/auth/login          → 微信登录（code → openid → JWT）
GET    /api/user/info            → 获取用户信息

GET    /api/bills                → 账单列表（分页 + 筛选）
POST   /api/bills                → 新增账单
PUT    /api/bills/:id            → 修改账单
DELETE /api/bills/:id            → 删除账单

GET    /api/bills/stats          → 统计数据（月度汇总、分类占比）
GET    /api/categories           → 分类列表
POST   /api/categories           → 新增自定义分类
```

**关键实现细节：**
- 所有 `/api/bills*` 接口都需要 `Authorization: Bearer <token>` 头
- `/api/bills/stats` 用 SQL 聚合查询：`SELECT category, SUM(amount), strftime('%Y-%m', bill_date) ...`
- 分页参数：`?page=1&pageSize=20&type=expense&month=2026-07`

```json

  "outputDirectory": "front/unpackage/dist/build/h5",
  "functions": {
    "api/**/*.js": {
      "runtime": "nodejs20.x"

  "rewrites": [
    { "source": "/api/(.*)", "destination": "/api/$1" }
```

## 八、面试话术准备

### Q：为什么用 Vercel Serverless 而不是传统服务器？
> "这个项目是个人记账工具，用户量不大。Vercel 免费套餐完全够用，而且前端 H5 和 API 可以统一部署在同一个域名下，不用配 CORS，也不怕跨域。实际企业项目里如果流量大，Serverless 换成 Express 独立部署也很方便，代码逻辑不用大改。"

### Q：为什么选 Turso 而不是 MySQL？
> "Turso 基于 SQLite，免费 9GB 对于个人工具绰绰有余。它是边缘数据库，全球多个节点就近访问，延迟很低。而且它兼容 SQLite 语法，本地开发用 SQLite 文件，上线无缝切换。如果后续要迁移到 MySQL，Drizzle ORM 改一行配置就行。"

### Q：小程序登录流程是怎样的？
> "前端调 `uni.login` 获取微信临时 code → 发到后端 `/api/auth/login` → 后端拿 code 调微信接口换取 openid → 查数据库，新用户自动注册 → 签发 JWT 返回前端 → 前端存 storage，后续请求带 `Authorization: Bearer xxx`。"

### Q：你怎么处理 H5 和小程序的差异？
> "用 uni-app 的条件编译，`#ifdef H5` 和 `#ifdef MP-WEIXIN` 分别走不同的登录逻辑。H5 因为没有微信环境，退化为手机号+验证码登录（或游客模式）。数据请求层封装在 `request.js` 里，业务页面不感知平台差异。"
